关于这份档案

建立于 2026 年 10 月 16 日 · 最近更新 2026 年 10 月 16 日

这是我学习全栈开发的个人档案页。它同时是 HTML 领域阶段项目的参考实现： 整个页面只用 HTML 和 CSS 写成，没有一行 JavaScript， 没有构建工具，没有任何依赖。

把 style.css 的 <link> 注释掉再刷新， 你会看到一个没有样式但顺序完全正确、内容完全可读的页面。 这是检验语义结构是否正确的最直接方法。

学习目标

短期目标是能独立把一个想法做成上线可访问的产品。为此需要掌握：

  • 用正确的语义结构表达内容，而不是靠 <div> 堆砌
  • 用 CSS 控制呈现，让结构与样式彻底分离
  • 用 TypeScript 建立可维护的前端与后端代码
  • 把成品部署到自己的服务器上并长期维护

学习计划

第一期的主线是「能上线」。顺序不能随意调换，因为每一步都依赖前一步：

  1. HTML —— 先能正确地表达内容。这一步做不扎实，后面所有布局和无障碍工作都要返工。
  2. CSS —— 再能控制呈现。重点是盒模型、层叠与继承、Flexbox 与 Grid。
  3. JavaScript —— 使用已有的 javascript.info 资源，不重造教程。
  4. TypeScript —— 为后续的 Vue 与 Node.js 打底，重点是类型推导与泛型。
  5. Vue 3 + Vite —— 前端主线框架，用组合式 API 与 <script setup>。
  6. Node.js + Fastify —— 后端主线，重点是请求生命周期与插件机制。
  7. SQL + PostgreSQL —— 数据库主线，先手写 SQL 再用 Prisma 做 ORM。
  8. Git —— 贯穿全程，不是单独的一步。
  9. Linux 基础 —— 服务器操作的最小集。
  10. Docker + Nginx —— 把成品部署到自己的服务器上。

学习笔记

只记录那些「查了资料才搞明白、且以后还会再遇到」的问题。

为什么 <p> 里不能放 <div>

2026 年 10 月 16 日

因为解析器在 <p> 内部遇到块级元素的开始标签时， 会先自动闭合当前的 <p>。这不是浏览器 bug， 而是规范里写明的容错行为。实际生成的 DOM 是 <p></p><div>…</div>， 中间那个空的 <p> 会带来意想不到的外边距。

<section> 不加 aria-labelledby 等于白写

2026 年 10 月 16 日

按 HTML-AAM 的映射表，<section> 只有在拥有可访问名称时 才映射为 region 角色，否则映射为 generic—— 和 <div> 在无障碍树上没有区别。 而子元素里有个 <h2> 并不会自动给父元素名称， 必须显式用 aria-labelledby 指过去。

相对 URL 会丢掉最后一段路径

2026 年 10 月 16 日

当前地址是 /docs/html/links.html 时， href="../css/" 解析为 /docs/css/； 但当前地址是 /docs/html（没有结尾斜杠）时， 同样的 href 解析为 /css/—— 因为 html 被当作文件名丢掉了。 这就是「本地双击打开正常，部署后 404」的常见原因。

常见问题

为什么不直接学框架？
框架解决的是「组织大量交互逻辑」的问题。在只有一个静态页面时， 框架带来的复杂度远大于收益，而且它掩盖了 HTML 与 CSS 的真实行为。
进度数据存在哪里？
哪都没存。这个参考实现只有 index.html 与 style.css 两个文件， 表里的数字是直接写进 <td> 的文本，页面没有任何脚本、 没有 localStorage，也没有后端。
这个页面能直接部署吗？
可以。它是两个文件（index.html 与 style.css）， 放到任何能提供静态文件的地方都能访问， 包括 VPS 上的 Nginx、 局域网里的一台机顶盒，或者直接双击用浏览器打开。
